# VirtualList —— 原生 JS 不等高虚拟滚动列表

不依赖任何框架(React/Vue)与第三方虚拟列表库,仅用原生 HTML/CSS/JavaScript
实现的大数据量、不等高条目虚拟滚动列表。只渲染可视区域与缓冲区内的真实 DOM
节点,其余内容用一个撑起总高度的占位元素代替。

## 文件结构

| 文件 | 说明 |
| --- | --- |
| `virtual-list.js` | 虚拟列表核心组件(单文件、零依赖,浏览器 / Node 双环境) |
| `index.html` | 演示页面:5000 条随机不等高数据 + 调试模式 |
| `test.js` | 自动化测试(手写 mock DOM + 自制 assert,`node test.js` 运行) |
| `server.go` | 可选的本地静态文件服务器(Go 标准库) |

## 快速开始

```bash
# 方式一:直接用浏览器打开(index.html 无模块加载,file:// 即可)
open index.html

# 方式二:本地静态服务器
go run server.go   # 然后访问 http://localhost:8080

# 运行自动化测试
node test.js
```

## 数据结构

组件为每个条目维护三张表(长度均为 `count`):

```
heights[i]  第 i 条的高度:未测量时为估算值 estimatedHeight,测量后为真实值
measured[i] 第 i 条是否已真实渲染并测量过
offsets[i]  高度前缀和(长度 count+1):第 i 条的顶部偏移,
            offsets[count] 即列表总高度(占位元素的高度)
```

DOM 结构:

```
container (固定高度, overflow-y: auto, 监听 scroll)
└── phantom (占位元素, height = offsets[count], position: relative)
    └── item nodes (position: absolute, transform: translateY(offsets[i]))
```

另有两个运行时结构:

- `nodes: Map<index, DOMNode>` —— 当前真实渲染的节点;
- `pool: DOMNode[]` —— 回收待复用的节点对象池。

## 高度动态测量与位置修正算法

条目真实高度未知前,`heights[i]` 一律用 `estimatedHeight` 占位。每次渲染后
执行一次「测量—修正」:

1. **测量**:遍历 `nodes` 中当前渲染的节点,读取 `offsetHeight`。只要渲染过
   就标记 `measured[i] = true`(即使真实值恰好等于估算值);若与记录值不一致,
   更新 `heights[i]`,并记录本次最小的被修正下标 `dirtyFrom`。
2. **后缀重算**:从 `dirtyFrom` 起重算累积偏移表后缀
   `offsets[i+1] = offsets[i] + heights[i]`。只重算受影响的后缀,而非全表;
   同一帧内多个条目被修正也只重算一次。随后同步更新占位元素高度,保证
   滚动条总高度与(当前已知的)内容高度一致,不会到底部出现空白或截断。
3. **锚点保持**:修正前记录当前滚动位置锚点(`anchorIndex` = 二分查找
   `scrollTop` 所在条目,`anchorOffset` = 条内偏移)。若 `dirtyFrom <=
   anchorIndex`(被修正的条目在视口锚点之前),修正后恢复
   `scrollTop = offsets[anchorIndex] + anchorOffset`,视口内容不跳动。
4. **迭代收敛**:高度修正改变了 `offsets`,可视区间可能随之变化,因此
   修正后再渲染一轮,直到高度表无变化(主循环带 20 次上限保护)。

所有条目都被测量过后,`offsets[count]` 精确等于真实内容总高度(测试用例 1
验证收敛)。

## 二分查找定位

`offsets` 单调不减,给定任意 `scrollTop`,用二分查找定位起始条目:

> 找到满足 `offsets[i] <= scrollTop` 的最大 `i`,夹取到 `[0, count-1]`。

复杂度 O(log n),不从头线性扫描。可视区间端点(含上下缓冲区)都用同一
查找得出;高度表被修正后,查找基于更新后的 `offsets` 即时生效(测试用例
2、3 验证与线性扫描基准完全一致)。

## 节点复用与回收策略

- 每次渲染先计算目标区间 `[start, end]`(可视区域 + 缓冲区);
- **回收**:`nodes` 中落在区间外的节点从 DOM 摘下,放入 `pool`,不销毁;
- **复用**:区间内缺少的节点优先从 `pool` 弹出复用,池空才新建;
- **防残留**:节点被指派给新条目时,调用方约定的 `renderItem(node, item,
  index)` 必须完整覆盖节点内容(演示中用 `innerHTML = ...` 整体替换),
  组件同时更新 `dataset.index` 等标记。测试用例 4 验证:复用节点的内容
  与其新服务的条目完全一致,无旧内容残留;滚动全程创建的 DOM 节点总数
  远小于条目数(千级条目只创建个位数节点)。

滚动事件经 `requestAnimationFrame` 节流,每帧最多一次渲染。

## 演示页面功能

- 5000 条随机数据(固定种子,可复现):约 30% 带 80~300px 图片占位,
  其余为 1~6 行文本,高度差异明显;
- **调试模式**开关:实时显示当前渲染区间、真实 DOM 节点数、对象池大小、
  占位总高度、已测量条目数、估算误差(平均/最大),并给真实渲染的节点
  描边、给占位元素描边,直观看到「哪些 DOM 真实存在」;
- 工具栏:跳转指定条目、回顶部、到底部、随机改变 50 个条目高度
  (模拟内容变化,验证动态重测量与偏移修正)。

## 自动化测试

`node test.js`,不引入测试框架:手写最小 mock DOM(只实现组件用到的
API)+ 自制 `assert`。覆盖:

1. **高度估算与修正收敛**:滚动全程后所有条目被测量,总高度精确收敛到
   真实高度之和,累积表自洽;
2. **二分查找正确性**:高度表更新后,2000 个随机位置(含边界与越界)的
   二分结果与线性扫描基准一致;
3. **快速跳跃滚动**:50 次随机大幅跳跃后,视口内条目全部有真实 DOM 节点,
   渲染区间端点与二分查找结果一致,跳到底部最后一条可达;
4. **节点复用**:滑出节点被回收复用、无旧内容残留,DOM 节点创建总数有界;
5. **动态高度变化**:条目内容变化后 `refresh()` 重新测量,总高度按差值
   修正到新的真实值。
